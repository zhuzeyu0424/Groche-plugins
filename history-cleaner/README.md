# Roche 记录清理 0.1.1

[安装地址](https://raw.githubusercontent.com/zhuzeyu0424/Groche-plugins/main/history-cleaner/plugin.json?v=0.1.1)

在 Roche「插件 App 管理」粘贴安装地址。首次安装后刷新 Roche。

## 入口

- 线上私聊或群聊：打开当前聊天的「搜索聊天记录」，搜索框下方点击「批量清理」。展开日历时，按钮仍在日历上方。
- 线下：打开「历史记录」，标题下方点击「批量清理」。

入口读取当前窗口的真实会话 ID，同名角色互不混用。插件桌面入口提供使用说明和「检查入口」。

0.1.1 修复正式网页没有开发环境组件标记时两个按钮都不出现的问题。使用 Roche 当前生产 Vue 的真实组件树确认所属会话，不依赖角色名称或全局最近会话。

## 使用

1. 先在 Roche 导出并保存一份完整备份。
2. 线上按最早条数或日期选择；线下按归档多选，可用日期缩小范围。
3. 点击「预览清理范围」，核对实际条数和时间。
4. 可额外导出所选原文 JSON。它是可阅读的原文副本，不是 Roche 原生完整备份，也不能直接用作 Roche 恢复文件。
5. 确认已保存完整备份，再点「确认删除」。

默认只选择已有总结进度的线上记录、已找到归档摘要的线下正文。若取消此限制，未进入记忆的细节可能丢失。总结进度不代表摘要涵盖原文全部细节。

线上默认至少保留最近 500 条，并强制保留当前短时上下文所需范围。收藏、置顶、书签、系统与记忆消息会跳过。日期使用设备本地时区，结束日期包含当天。

线下只删除选中归档会话的剧情消息，保留摘要消息、事实/核心/向量记忆及很小的归档索引。因此历史列表中仍可能看到日期条目，但已清理的原文不能再回看。不会调用原生的「删除归档」操作。

## 数据与兼容

- 不会自动清理，插件本身不调用聊天、识图或生图 API。若原本启用了角色动态等原生后台功能，它们的调度仍由 Roche 控制。
- 不上传聊天记录或备份。只有用户点击导出时请求浏览器保存本地 JSON。
- 不在本机建立回收副本；删除后恢复原文需要之前保存的备份。
- 每次删除前重新核对范围，按最多 200 条一批处理；可停止后续批次。已经完成的批次不会撤销。
- 核对已有记忆记录是否保持完整。检测到并发修改会停止，不会自动覆盖新数据。
- 当前聊天在生成、加载或通话时拒绝清理。
- 使用经过签名核对的 Roche 原生消息删除函数同步 UI 与数据库。遇到不支持的主程序版本会拒绝操作，不使用猜测性删除降级。
- 预计释放量按所选记录的 JSON 大小估算；浏览器实际存储统计、附件与运行内存可能不同。
- 关闭后重新打开原生历史可刷新列表。

开发验证使用隔离的 WebKit 测试数据库与模拟聊天，不执行用户数据删除。iPhone 真机仍需用户验证入口和浏览器下载行为。
