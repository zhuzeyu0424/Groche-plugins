# 表情识别 0.1.2

Roche 独立插件。使用单独配置的视觉 API 观察双方原生表情包，在角色下一轮回复前，将描述、发送者和对应消息提供给当前聊天。

## 安装

在 Roche 插件 App 管理中安装：

https://raw.githubusercontent.com/zhuzeyu0424/Groche-plugins/main/sticker-vision/plugin.json?v=0.1.2

安装后刷新 Roche，在「表情包库 → 识别设置」打开。也可以从插件 App 打开「表情识别」。

填写独立的 API 地址、Key、视觉模型，打开「自动识别」并保存。支持 Chat Completions 兼容接口；填写站点根地址或 `/v1` 时会补全 `/v1/chat/completions`。其他路径按填写的完整接口地址调用。所选模型必须支持 `image_url` 图片输入，接口须允许 Roche 网页跨域访问。

填好地址和 Key 后，可点击视觉模型旁的「拉取」，从下拉列表选择，也可继续手动填写。拉取读取当前表单，不必先保存或填写模型；只发送一次 `GET /models`，不会试识图、自动选型或失败后换模型。完整接口路径会保留前缀，例如 `/proxy/chat/completions` 对应 `/proxy/models`。站点需返回兼容的 `data[].id` 模型列表；列表不代表识图支持、账号权限或实时可用状态。换地址或 Key 会清空旧列表；失败不清除已填写的模型。

先从「试识别一张」选择图片，再点「识别测试」验证真实接口。选择文件、保存设置本身不调用 API。没有随插件附送的 API Key。

## 自动识别排查

支持你从原生表情面板发送的图片表情包，也支持角色发送的原生表情包；角色回复前才会进行本轮识别。打开「自动识别检查」可看到最近一次聊天检查：是否读到表情、是否在启用前发送、是否有可读图源，以及是否提供了画面描述。这里只保留一条本机检查摘要，不保存聊天正文、图片或密钥，也不额外调用识图。启用后还没收到聊天触发、读取失败或不支持的入口会明确显示。

0.1.2 将聊天读取等待从 2.5 秒放宽到 8 秒，避免手机较慢时过早跳过；配置验证失败也会写入识别缓存。没有重扫历史表情、自动重试付费请求或修改 Roche 原生记录。该版提供排查依据，不表示已确认所有空缓存都是同一个原因。

## 使用

- 照常从原生表情面板发表情包，角色下次正常回复前识别。
- 首版接入线上单人聊天，双方的原生 `sticker` 消息都支持；不处理气泡 emoji、群聊或线下归档。
- 启用后新发送的图片会自动识别，不自动扫描历史表情库。每轮最多两张新图；读取最近 24 条消息中的最多六条表情消息。
- 图源与图片内容缓存避免重复识图；缓存最多 300 条描述，不重复存储表情原图。
- JPG、PNG、WebP 等按静态画面分析；GIF 可读取时只取一张静态画面，不能理解完整动画过程。
- 图床阻止浏览器取图时，HTTPS 静态图地址可直接交给视觉接口读取；该接口仍需要能访问图源。
- 超时、HTTP 失败和未完成尝试不自动重发。失败可在缓存页明确确认后重试，可能再次计费。
- 识别缓存支持修正描述；清缓存仅操作本插件的数据库，清后重识别可能计费。
- 图片内容只作为数据提供，人物、情绪和语气可能识别错误。角色结合聊天理解，识别失败时不宣称看懂。

## 数据

API 配置及最近一条检查摘要保存在当前网站的本机 localStorage；描述和尝试记录保存在独立 IndexedDB。没有上传到 GitHub 的密钥或图片，也没有修改原生表情、聊天记录或记忆。识别时图片会发送至你配置的 API。插件缓存和配置不保证包含在 Roche 原生备份中；首次换设备需重新配置。

## 验证

基于 2026-11-05 至 11-06 Roche 公开脚本确认异步 `contextProvider`、用户原生表情消息地址和表情包库结构。WebKit 自动测试覆盖图像输入、双方归属、对话隔离、内容去重、失败与重装防重发、手动重试、缓存修正与清理、弹窗层级及三种屏幕尺寸，以及模型列表路径、下拉选择、错误处理和过期请求取消。另覆盖 2.7 秒慢速读取、空缓存的跳过原因、检查摘要不泄露密钥和原生消息不变。测试使用模拟接口，未调用用户付费服务；仍需在真实手机与所选视觉 API 上试用。
